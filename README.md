# Монитор упоминаний Яндекса

Локальное Windows-приложение с отдельным desktop-окном. Яндекс Браузер открывает реальную выдачу, выполняет JavaScript, а `puppeteer-core` управляет им через Chrome DevTools Protocol. Данные сохраняются встроенным модулем `node:sqlite`, экспорт создаётся в формате XLSX.

## Установка готовой программы

- Требуется Windows 10/11 x64 и установленный Яндекс Браузер.
- [Скачайте последнюю Windows-сборку](https://github.com/code-spark-pro/mention-monitor-windows/releases/latest/download/Mention-Monitor-Setup-1.0.0.exe).
- Запустите `Mention-Monitor-Setup-1.0.0.exe`.
- Выберите папку установки и завершите мастер. Права администратора не требуются.
- Откройте «Монитор упоминаний» через меню «Пуск» или ярлык рабочего стола.
- Node.js, npm и исходный код на компьютере пользователя не нужны.

Установщик пока не подписан коммерческим сертификатом, поэтому Windows SmartScreen может запросить дополнительное подтверждение издателя.

## Данные программы

База, логи, уникальный временный профиль браузера и экспорты находятся в `%APPDATA%\Mention Monitor`. Для каждого запуска создаётся отдельный профиль, поэтому оставшееся окно Яндекс Браузера не блокирует новый поиск. Они не записываются в `Program Files` и сохраняются при удалении программы.

## Запуск из исходников

1. Клонируйте репозиторий и дважды откройте `start_monitor.cmd`.
2. Если Node.js не установлен, скрипт скачает переносную версию в `.runtime` без прав администратора.
3. При первом запуске скрипт автоматически выполнит `npm install`.
4. Панель откроется по адресу <http://127.0.0.1:3080>.
5. Не закрывайте консоль и окно Яндекс Браузера во время парсинга.

Ручной запуск:

```powershell
git clone https://github.com/code-spark-pro/mention-monitor-windows.git
cd mention-monitor-windows
npm install
npm test
npm start
```

Desktop-режим для разработчика и сборка установщика:

```powershell
npm install
npm test
npm run desktop
npm run dist:win
```

Если GitHub CDN недоступен в текущей сети, перед сборкой можно задать зеркала загрузки:

```powershell
$env:ELECTRON_MIRROR = 'https://npmmirror.com/mirrors/electron/'
$env:ELECTRON_BUILDER_BINARIES_MIRROR = 'https://npmmirror.com/mirrors/electron-builder-binaries/'
npm run dist:win
```

## Поиск

- Парсер сначала открывает обычный Яндекс.Поиск и переходит по вкладке «Новости», если она присутствует в текущем интерфейсе.
- Если Яндекс скрывает вкладку, используется официальный адрес `yandex.ru/news/search`; сейчас он автоматически открывает активную вкладку «Новости» на `dzen.ru/news/search`.
- Результаты общей веб-выдачи не собираются: источник материалов — только вкладка «Новости».
- Произвольный текст передаётся в Яндекс без кавычек. Все слова должны присутствовать, но порядок и словоформы могут отличаться.
- Аббревиатуры длиной до пяти букв, например `РЦВДО`, проверяются целиком без учёта регистра.
- «Точная фраза» обрамляет весь текст кавычками, требует строгое совпадение без словоформ и отключает извлечение даты.
- Поддерживаются даты `ДД.ММ.ГГГГ`, `ГГГГ-ММ-ДД`, `ДД месяц ГГГГ`.
- Ручной диапазон перекрывает период и дату из запроса.
- Дата из запроса с периодом создаёт симметричный диапазон вокруг даты.
- Период без даты передаётся через `within`.
- Каждый сюжет загружается и проверяется по всем словам либо по точной фразе. В таблицу сохраняются прямые ссылки сайтов-источников, а не URL агрегатора Дзена.
- Результаты группируются по ключевому упоминанию; итоговая строка показывает количество публикаций и уникальных сайтов.
- Отдельный результат можно удалить кнопкой в его строке.
- Дата берётся из метатегов, `<time>` или сниппета и проверяется повторно.
- Whitelist и blacklist передаются операторами `site:`/`-site:` и применяются повторно к URL.

При SmartCaptcha вкладка остаётся открытой. В режиме «остановить» приложение опрашивает DOM каждые две секунды и продолжает после прохождения капчи; в режиме «пропустить» текущая страница выдачи пропускается.

## Профили

- **Временный**: уникальный каталог `data/browser-profile-<process>-<random>` для каждого экземпляра, выбран по умолчанию.
- **Пользовательский**: путь задаётся в панели. Перед использованием закройте обычные окна Яндекс Браузера, иначе профиль может быть заблокирован.

## API

- `GET /api/status` — интернет, браузер и путь к нему;
- `POST /api/search` — запуск, ответ `202 {jobId}`;
- `GET /api/jobs/:id` и `GET /api/search/:id` — состояние задания;
- `GET /api/results` — `page`, `limit`, `sort`, `order`, `q`, `includeUnknownDate`, `jobId`; ответ содержит строки и агрегаты по запросу;
- `GET /api/history`, `POST /api/history/:id/rerun`, `DELETE /api/history`;
- `GET/POST/PUT/DELETE /api/presets`;
- `GET/PUT /api/settings`;
- `POST /api/export` — `{scope:"current"|"all",jobId}`;
- `DELETE /api/results/:id` — удалить отдельный результат;
- `DELETE /api/results` — удалить все результаты.

Сервер слушает только `127.0.0.1`. Офлайн-режима нет: перед каждым заданием выполняется запрос к `https://ya.ru` с тайм-аутом пять секунд, а состояние обновляется каждые десять секунд.

В desktop-режиме Windows назначает случайный свободный локальный порт, а API требует случайный 256-битный токен текущего запуска. Одновременно работает только один экземпляр программы. Поисковые задания выполняются последовательно, чтобы Яндекс Браузер и его профиль не конфликтовали.

## Хранение и безопасность

При запуске из исходников база находится в `data/mention-monitor.db`, логи в `logs/parser.log`, экспорт в `exports/`. В установленной программе эти каталоги находятся в `%APPDATA%\Mention Monitor`. URL нормализуются, UTM/`yclid`/`gclid` удаляются. Значения SQL передаются параметрами. Backend ограничивает размер JSON и не публикуется во внешнюю сеть.

Для будущего Yandex Search API предусмотрен интерфейс `SearchProvider`; текущая реализация называется `YandexHTMLProvider`, заготовка замены — `YandexAPIProvider`.
